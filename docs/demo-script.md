# Muster demo video script (≤ 5:00)

Target runtime **4:30** (30 s buffer against the 5:00 cap). Voiceover pace ~140 words/min, so the spoken total must stay **≤ ~640 words**. Current voiceover: **575 words** (≈ 4.1 min at 140 wpm).

Follows CLAUDE.md §8.1 (purpose → value for both sides → walkthrough incl. shop view → next steps). Northgate Land Systems is **fictional**. All shops in the demo are **synthetic** and labelled as such on screen. Training partners are **example, not affiliated**. The ITB rules are **simplified for the demo**.

The shop view visits the demo shop **twice**: once on `/gaps` (Gaps & Training) *before* funding, when its readiness card still says "Get CWB W47.1," and once *after* funding via **"See it from the shop's side,"** when that card has already moved on to the next gap (ISO 9001). Don't show the CWB readiness message after funding — by then the shop already has that training pending, so the card reads differently.

## Pre-recording checklist

1. `git pull` and confirm `main` runs: `make dev` (engine :8000, web :3000).
2. `make demo-check` passes all 8 steps. If the engine is flaky, confirm `make fixtures-check` passes so fixtures mode is a safe fallback.
3. **Record from a production build**, not `next dev`: `cd web && npm run build && npx next start -p 3000`. This keeps the Next.js dev indicator badge off screen.
4. **`make reset-demo`** immediately before recording (program state must be `empty`; no parts uploaded, nothing funded). Then, in the browser, click the header's **"Reset demo"** button too, so client-side demo state is clean. Repeat both before every retake.
5. Browser: Chrome, fresh profile or guest window, resolution **1920×1080** (preferred) or **1280×720**, **zoom 100–110%**, bookmarks bar hidden (Cmd+Shift+B), no extensions visible, notifications off (macOS Focus mode on).
6. Pre-open tabs: `/program`. Do not pre-load `/scorecard` or `/gaps` (they should load live after routing).
7. Check the footer disclaimer and the **Synthetic** / **Fictional prime** / **example, not affiliated** labels are visible on each screen.
8. Know the fallback: the web app falls back to `/data/fixtures` with a visible mode badge — **"Demo mode · fixtures"** (vs. **"Live API"**) — if the API is down. Confirm it renders the same numbers before you start.
9. Rehearse the voiceover once with a timer; it must end by 4:30.
10. Mic check; quiet room; record voiceover separately if the room is noisy and lay it over the screen capture.

## If something breaks mid-recording

- **Do not stop to debug.** Stop the engine (or let it fail) and reload the page: the web app switches to fixtures and shows the **"Demo mode · fixtures"** badge. The numbers are the same fixture numbers, so the voiceover still matches. Keep going and mention nothing, or say "running in demo mode".
- If the map tiles fail, continue; the jobs table and popover carry the controlled-job point.
- If "Fund training" returns 409 (already funded), run `make reset-demo` and click **"Reset demo"** in the browser, then redo Load → Route → Fund; trim the gap in editing.
- If one segment goes badly, re-record just that segment from a reset state and cut it in; the voiceover is segmented by timestamp for exactly this reason.
