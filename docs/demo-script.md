Target runtime **4:40** (20 s buffer against the 5:00 cap). Voiceover pace ~140 words/min, so the spoken total must stay **≤ ~640 words**. Current voiceover: **624 words** (≈ 4:27 at 140 wpm; every segment runs at 115–143 wpm; per-row counts in the word budget below the script). Every ON SCREEN label below was re-checked against a production build in fixtures mode on 2026-09-27 by clicking through the whole script in a browser (laptop 1280×720, phone 390×844); the search counts were also checked live against Neo4j. Arrows (→) at the end of a button label are drawn as icons. The **Portals** beat (4:02–4:28) replaced the old optional Real shops segment. If a take runs long, drop its second search (Armatec) first, then the Tallowfield half (about 8 s each). Follows CLAUDE.md §8.1 (purpose → value for both sides → walkthrough incl. shop view → next steps). Northgate Land Systems is **fictional**. All shops in the routing demo are **synthetic** and labelled as such on screen; the real shops shown on `/network` are **public data, unverified, not affiliated** and are never routed. Training partners are **example, not affiliated**. The ITB rules are **simplified for the demo**.

The shop's side is shown **twice**: briefly on the desktop `/shops/syn-012` *before* funding (readiness card still says "Get CWB W47.1"), then on the **phone** (`/m`, docs/app-spec.md §2.11), where the shop answers offers, asks the prime to fund W47.1, and sees its welders in training *after* the laptop clicks Fund (its readiness card has moved on to ISO 9001 by then). Don't show the CWB readiness message after funding.

Wording: W47.1 is a **company** certification; the prime funds **qualifying 4 welders under W47.1** (tickets), and the company also needs a qualified supervisor and approved procedures. Never say "certify 4 welders". In the voiceover say "four welder training seats": the $96K is 4 × $24K new-welder seats, all-in including stipend (assumption, `data/rules/training_costs.json`). Say "CWB-qualified welders" or "a shortage of qualified welders", never "the welder shortage" (Job Bank rates the general Ontario welder outlook "very limited"). Don't mention the 35 Ukraine vehicles; they are a separate commitment from the London deal. The engine/fixture package title still says "Certify 4 welders…" until after the freeze; the web shows "Qualify 4 welders (FCAW/GMAW) under CSA W47.1…" on `/gaps` and the shop's phone, and the defence company's phone (`/m/prime`) shows "Qualify 4 welders under CSA W47.1" on the TP-01 card.

## Pre-recording checklist

1. `git pull` and confirm `main` runs: `make dev` (engine :8000, web :3000). Start Neo4j and load the graph: `make graph-up` (or `make graph-load` to force a reload), so Find suppliers shows **"Powered by Neo4j"**.
2. `make demo-check` passes all 8 steps. If the engine is flaky, confirm `make fixtures-check` passes so fixtures mode is a safe fallback.
3. **Record from a production build**, not `next dev`: `make demo` (builds with the same-origin `/engine` proxy, starts engine :8000 + web :3000 and prints the phone URL for a real phone on the same Wi-Fi; `/phone` shows a QR code). This keeps the Next.js dev indicator badge off screen. Do **not** run `make demo-seed` before recording: the script starts from the empty state.
4. **`make reset-demo`** immediately before recording (program state must be `empty`; no parts uploaded, nothing funded). Then, in the browser, click the header's **"Start over"** button too, so client-side demo state is clean, and sign out (account menu → **Sign out**). Repeat all three before every retake.
5. Browser: Chrome, fresh profile or guest window, resolution **1920×1080** (preferred) or **1280×720**, **zoom 100–110%**, bookmarks bar hidden (Cmd+Shift+B), no extensions visible, notifications off (macOS Focus mode on).
6. Pre-open tabs: `/program`. Do not pre-load `/scorecard` or `/gaps` (they should load live after routing).
7. **Phone window (2:24–4:02).** A second Chrome window sized to **390×844** (DevTools device toolbar, or a narrow window; `/m` draws a phone frame on wide screens) on `/m/shops/syn-012`, same engine, placed beside the laptop window. Open it after "Match jobs to shops" if you can; if it was already open, it reloads itself once when the laptop routes (live mode). Clear its localStorage before each take (a fresh guest window is easiest).
8. **Phone fallback without the engine:** open both windows in the *same* browser profile with `?mode=fixtures` (e.g. `/program?mode=fixtures` and `/m/shops/syn-012?mode=fixtures`). Actions sync between them through `localStorage` (`muster.app.v1`), and the phone repeats the laptop's Load / Match / Fund steps on its own. Rehearsed end to end: same beats, same numbers.
9. Dismiss laptop toasts (×) before clicking **Fund training**: at 1280×720 the activity toast stack sits bottom-right, next to the TP-01 Fund row.
10. Check the footer disclaimer and the **Synthetic** / **Fictional prime** / **example, not affiliated** / **Public data, unverified, not affiliated** labels are visible on each screen.
11. Know the fallback: the web app falls back to `/data/fixtures` with a visible mode pill — **"Demo data"** (vs. **"Live"**) — if the API is down. Confirm it renders the same numbers before you start. Search works in both: with Neo4j down in Live mode the badge reads **"In-memory graph"**; in Demo data it reads **"In-memory graph · demo data"**. The results are the same.
12. Rehearse the voiceover once with a timer; it must end by 4:50 (target 4:40). Over 4:50: drop the Portals beat's second search, then its Tallowfield half.
13. Mic check; quiet room; record voiceover separately if the room is noisy and lay it over the screen capture.

## If something breaks mid-recording

- **Do not stop to debug.** Stop the engine (or let it fail) and reload the page: the web app switches to fixtures and shows the **"Demo data"** pill. The numbers are the same fixture numbers, so the voiceover still matches. Keep going and mention nothing, or say "running in demo mode".
- If the map tiles fail, continue; the jobs table and popover carry the controlled-job point.
- If "Fund training" returns 409 (already funded), run `make reset-demo` and click **"Start over"** in the browser, then redo Load → Match → Fund; trim the gap in editing.
- If the phone misses a step in live mode (no toast on the laptop within ~4 s), tap **Refresh** in the phone header; if still stuck, reload the phone window. Beats 2–4 re-read the engine on every event.
- If one segment goes badly, re-record just that segment from a reset state and cut it in; the voiceover is segmented by timestamp for exactly this reason.
